# Установка и использование · 0.5.0

Codex Quota Guard предоставляет рекомендательные проверки квоты. Требуются Python 3.10+, POSIX (Linux/macOS) и официальный Codex CLI с уже выполненной аутентификацией и аккаунтом, соответствующим условиям использования. Во время работы используется только стандартная библиотека Python. Исполняемый файл должен находиться в доверенном PATH.

## Установка

```sh
codex plugin marketplace add knight-bo/codex-quota-guard
```

Перезапустите настольное приложение, выберите Codex Quota Guard Local, установите и включите плагин. Плагин работает только в настольном приложении и распространяется через загрузку с GitHub. Публикация на GitHub не означает одобрение для публичного каталога плагинов. Установка не запускает мониторинг или исследовательские задачи и не создаёт автозапуск или расписание.

## Проверка и запуск

Примеры запросов: «Покажи остаток квоты Codex», «Следи за этой задачей: целевой остаток 80%. Когда приблизимся к нему, сначала спроси, приостановить ли задачу. Проверяй каждые 30 секунд», «Останови мониторинг квоты». Разовый запрос не запускает постоянный мониторинг. Пожелание о размере резерва само по себе тоже не является запросом на запуск.

Выполняйте команды из корня плагина. Замените STATE абсолютным путём к одному и тому же приватному каталогу состояния вне репозитория и кеша плагинов. Каталог должен принадлежать текущему пользователю, иметь права 0700 и находиться внутри доверенного доступного для записи родительского каталога. Вместо TASK укажите стабильный идентификатор конкретной задачи, проверенный хостом. Если задача неясна, сначала уточните её; не выдумывайте идентификатор. Не включайте в него пароли, токены и другие секреты. В сохранённом состоянии и выводе используется только хешированная привязка, без исходного идентификатора. Такая привязка не даёт права управлять задачей.

Для ручной проверки используется русский текст. Мониторинг под контролем хоста использует стандартный вывод JSON, чтобы хост мог читать состояние и события.

```sh
python3 scripts/quota_guard.py read --bucket codex --state-dir STATE --format text --locale ru
python3 scripts/quota_guard.py start --bucket codex --target 80 --task-key TASK --warn-margin 2 --confirm-margin 1 --interval 30 --state-dir STATE
```

Мониторинг запускается только по явному запросу. start — другое имя команды watch; она работает на переднем плане, а не как фоновая служба. До запуска постоянного мониторинга хост должен уметь поддерживать контролируемый фоновый сеанс, сохранять его дескриптор, читать события JSON и одновременно принимать ответы пользователя. Если это невозможно, объясните ограничение и выполните только разовую проверку. Не утверждайте, что постоянный мониторинг работает. Не обходите это требование с помощью nohup, скрытого демона или автозапуска.

## Целевой остаток и пороги

--target принимает любое конечное число от 0 до 100 включительно, в том числе 37.5. Это процент оставшейся, а не использованной квоты; выбор не ограничен заранее заданными значениями. В примере используются стандартные отступы: 2 процентных пункта для предупреждения и 1 для запроса подтверждения.

- Остаток ≤ 82%: событие warning.
- Остаток ≤ 81%: событие confirmation_required. Хост спрашивает: «Приостановить эту задачу, когда останется 80% квоты?»
- Остаток ≤ 80%: событие target_reached и запрет допуска новой работы: allow_new_work=false, причина confirmation_target_reached. Это решение, которое должен учитывать взаимодействующий с плагином исполнитель, а не фактическая приостановка задачи.

Достаточно достижения порога в любом применимом окне. Отступы измеряются в процентных пунктах; отступ предупреждения должен быть не меньше отступа подтверждения, а каждый порог ограничен сверху значением 100%. Отступы не изменяют сам целевой остаток. Если уже первое достоверное измерение не выше цели, сразу спросите: «Уже осталось не больше 80% квоты. Приостановить эту задачу сейчас?» Не описывайте состоявшееся пересечение как будущее. При цели 100 вопрос нужен сразу, даже если осталось 100%. Цель 0 не гарантирует защиты от полного исчерпания квоты. Если одно измерение вызывает несколько этапов, объедините вопросы, чтобы не спрашивать одно и то же несколько раз.

Режим --target нельзя сочетать с --reserve, --threshold или --buffer: такие сочетания отклоняются. Старый пример «резерв 10%, буфер 2 процентных пункта, запрет новой работы при остатке 12%» относится только к совместимому режиму резерва. Он не заменяет выбранную цель, в том числе ниже 10%. В целевом режиме порог допуска точно равен выбранной цели, а буфер равен 0.

## События, подтверждение и управление задачей

Событие CLI не доказывает, что пользователь уведомлён, сообщение доставлено, разрешение получено или задача приостановлена. Хост должен действительно задать вопрос, отдельно записать ответ пользователя и до действия проверить принадлежность задачи и наличие поддерживаемого способа управления. Молчание не означает согласия. Если такого способа нет, объясните препятствие и попросите пользователя выполнить действие вручную. Нельзя произвольно завершать процессы или приостанавливать облачные задачи. --target несовместим с --allow-interrupt.

Этап confirmation и список events в стандартном JSON нужны для решения со стороны хоста; pause_authorized и task_paused остаются false. События сохраняются не более одного раза, без гарантии доставки уведомлений. После перезапуска или пропуска события сверяйте текущий этап с реальной историей разговора и задавайте ещё не заданный вопрос. Отсутствие нового события не является согласием.

Хост может выполнить только явно разрешённое действие над конкретной задачей и только проверенным поддерживаемым способом. Прежде чем сообщить о приостановке, проверьте фактическое состояние задачи. Прежнее управляемое прерывание ограничено точной парой thread/turn, принадлежащей оркестратору и доступной через текущий app-server. Это не обход подтверждения и не гарантия приостановки с возможностью продолжения. Статус контрольной точки — unconfirmed. Подтверждение RPC-запроса прерывания не доказывает завершение задачи, сохранение контрольной точки или остановку всех отделённых рабочих процессов.

## Остановка, перезапуск и ограничения измерений

Для остановки выполните в другом терминале команду с тем же STATE:

```sh
python3 scripts/quota_guard.py stop --state-dir STATE --format text --locale ru
```

Убедитесь в исходном сеансе, что процесс завершился. Запрос остановки сам по себе этого не подтверждает. Также поддерживается Ctrl-C. Остановка мониторинга не останавливает наблюдаемую задачу. Изменение цели или настроек мониторинга требует нового явного согласования: сначала подтвердите завершение старого процесса, затем запускайте его с согласованными значениями.

Запрет допуска после достижения цели сохраняется при увеличении остатка, сбросе квоты и перезапуске с той же задачей и целью. Ничто из этого не возобновляет работу автоматически. Используйте --new-cycle только по явному запросу пользователя на новый цикл мониторинга и после остановки предыдущего процесса. Очистка состояния цикла не является разрешением приостановить или возобновить задачу и не доказывает её возобновление.

Из-за интервала опроса, задержек отчётности, повторных попыток и расхода другими клиентами при обнаружении остаток может уже оказаться ниже цели. Остановку точно на выбранном проценте гарантировать нельзя. Проверяйте каждое окно и время измерения. Кешированные, устаревшие, отсутствующие, синтетические или недостоверные данные не являются текущим остатком и не доказывают достижение цели или снятие условия. После времени сброса требуется новое достоверное измерение. Категория codex задаётся явно и не является универсальным соответствием для всех моделей.

При ошибках используйте обычные процедуры одобрения и входа. Не обходите ограничения изменением прав, аутентификации или CODEX_HOME. Не читайте напрямую файлы учётных данных и журналы сеансов. Мониторинг не покупает квоту и не даёт дополнительных прав управления задачами.

## Необязательные публичные объявления Tibo

Скажите «Следи за публичными объявлениями Tibo о сбросе каждый час», «Уведомляй только о completed и banked в Asia/Shanghai», «Проверь объявления один раз» или «Останови публичные уведомления». Используется отдельная команда `resetwatch`. Вопрос означает один `read`; запуск возможен только при явном запросе мониторинга. Хост должен контролировать процесс на переднем плане, читать JSON и использовать существующий локальный адаптер уведомлений. Если его нет, доступны только текст/JSON; об этом нужно сообщить. Установка не запускает мониторинг.

`planned` — план, не завершение; `completed` — сторонний отчёт об объявлении завершения; `banked` — сохранённый сброс без подтверждения получения и ручного применения; `manual_credit` — ручное начисление, условия которого нужно проверить в оригинале. Публичные сведения не подтверждают личную квоту, ничего не применяют и не возобновляют/приостанавливают исследования автоматически. Даже отметка провайдера «проверено напрямую» — его заявление, не независимое подтверждение и не официальный API.

Замените PUBLIC_STATE приватным абсолютным родительским каталогом вне репозитория/кэша. Отдельные `PUBLIC_STATE/public-reset-watch`, блокировка и токен остановки не меняют состояние квоты. Первая успешная загрузка молча создаёт базу. Исторические посты, дубликаты, перезапуски и старые состояния не повторяют уведомления. Переход planned→completed выдаёт только новое состояние. Смена фильтров не воспроизводит историю. Для смены настроек остановите процесс, проверьте завершение и перезапустите; остановка этого монитора не останавливает исследования или монитор квоты.

`--events` выбирает planned,completed,banked,manual_credit (все по умолчанию). `--interval`: 3600..86400 секунд, по умолчанию 3600. Ожидание сохраняется после перезапуска; отсрочка после ошибок ограничена 24 часами. `--max-age` ограничивает возраст кэшированных данных загрузки/проверки (172800 секунд, не меньше интервала и не больше 604800); `--event-age` — возраст новых постов (604800, диапазон 3600..2592000). Общий `--timeout`: 1..30 секунд (10), возможен ещё один тайм-аут сокета. `--timezone` — установленный пояс IANA, по умолчанию UTC; машинные даты остаются UTC. `--locale` сохраняет правила подстановки; поля и значения JSON не переводятся.

По умолчанию `--provider modelyard` читает только фиксированный публичный RSS `/feed.xml`. HTML-адаптер и произвольный `--provider-url` удалены; смена источника требует проверки кода. Категории RSS — сторонние отчёты, не официальная проверка. `fetched_at` отражает локальную загрузку; lastBuildDate/дата последнего поста не являются сигналом синхронизации. Старый корректный feed может создать базу, но полнота остаётся неизвестной. Область продуктов определяется предоставленным оригинальным текстом либо помечается неизвестной; заголовок/контекст — лишь заявление источника. Записи только о ChatGPT не отправляются как Codex/Work. Изменение категории одного поста получает `first_observed_status_at` и пометку локального изменения агрегатора, без выдуманной даты правки. Callback подключается лишь к существующим локальным уведомлениям хоста; доставка не проверена. Сеть/скачивание Library здесь блокируются; проверен напрямую переданный реальный обрезанный первый элемент. Robots не означает разрешение на повторное распространение; см. проверку источника.

Сетевой/HTTP-сбой, устаревшая проверка, неверные даты/формат или поддельный источник означают неизвестное, а не «сброс был/не был»; событий нет. Отсутствие новых событий при успешном опросе не доказывает отсутствие сброса. `status` — кэш, не новая проверка и не доказательство работы процесса. Журнал сохраняется до вывода: сбой может потерять доставку, а событие не доказывает уведомление пользователя. Сон, выход и задержки сети/провайдера прерывают покрытие. Нет гарантии реального времени или автозапуска; не нужны новый аккаунт, платный API, загрузка пользовательских данных или новые системные разрешения уведомлений.

```sh
python3 scripts/quota_guard.py resetwatch --help --locale ru
python3 scripts/quota_guard.py resetwatch read --state-dir PUBLIC_STATE --format text --locale ru
python3 scripts/quota_guard.py resetwatch start --state-dir PUBLIC_STATE --events completed,banked --interval 3600 --timezone Asia/Shanghai
python3 scripts/quota_guard.py resetwatch stop --state-dir PUBLIC_STATE --format text --locale ru
python3 scripts/quota_guard.py resetwatch status --state-dir PUBLIC_STATE --format text --locale ru
```

Сам публичный монитор требует только Python/POSIX/сеть и установленные данные часовых поясов IANA; официальная Codex CLI и аккаунт не нужны.

`--fixture FILE` работает только с `read`, без сети/аккаунта, с изолированным синтетическим состоянием; старая дата проверки корректно признаётся устаревшей.
