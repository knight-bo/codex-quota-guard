# 中文安装与使用指南 · 0.4.0

Codex Quota Guard 提供建议性的额度查询和监控。需要 Python 3.10+、POSIX 系统（Linux/macOS），以及已安装、完成正常身份验证且账户符合使用条件的官方 Codex CLI。运行时只依赖 Python 标准库。请使用可信 PATH 中的官方程序。

## 安装

```sh
codex plugin marketplace add knight-bo/codex-quota-guard
```

执行后重启桌面应用，选择 Codex Quota Guard Local，安装并启用。插件仅适用于桌面端，通过 GitHub 下载分发；GitHub 发布不代表获得公共插件目录审批。安装不会启动监控、研究任务，也不会配置自动启动或定时任务。

## 查询与启动

可以说：“查看 Codex 剩余额度”“监控这项任务，以剩余额度 80% 为目标；接近时先问我是否暂停，每 30 秒检查一次”或“停止额度监控”。单次查询不会启动持续监控；仅表达预留额度的偏好也不等于要求启动监控。

以下命令从插件根目录运行。将 STATE 替换为同一个可信、私有、由当前用户拥有的状态目录的绝对路径；其权限应为 0700，位于仓库和插件缓存之外，父目录必须可信且可写。将 TASK 替换为宿主已核实的具体任务的稳定标识；任务不明确时先询问，不能编造标识。TASK 不应包含密码、令牌或其他秘密；持久化状态和输出只使用其哈希绑定，不记录原始标识。该绑定不授予任务控制权限。

人工查看时使用中文文本；宿主监督运行的监控使用默认 JSON，以便读取状态和事件：

```sh
python3 scripts/quota_guard.py read --bucket codex --state-dir STATE --format text --locale zh
python3 scripts/quota_guard.py start --bucket codex --target 80 --task-key TASK --warn-margin 2 --confirm-margin 1 --interval 30 --state-dir STATE
```

只有明确请求才启动监控。start（watch 的别名）在前台运行，不是后台守护进程。启动持续监控前，宿主必须能将其放入受监督的后台会话，保留会话句柄、读取 JSON 事件，并始终让用户能够回复。如果无法同时维持监控和交互，应说明限制，只做单次查询，不能声称持续监控已经启动。不要通过 nohup、隐藏守护进程或自动启动项绕过这一要求。

## 剩余额度目标与触发点

--target 接受 0 至 100（含两端）的任意有限数值，包括 37.5；它表示剩余百分比，不是已用百分比，也不是几个固定档位。上例的默认边距为预警 2 个百分点、确认 1 个百分点：

- 剩余量 ≤ 82%：产生 warning 预警事件。
- 剩余量 ≤ 81%：产生 confirmation_required 事件，宿主应询问是否在剩余 80% 时暂停这项具体任务。
- 剩余量 ≤ 80%：产生 target_reached 事件，并以 allow_new_work=false 拒绝准入新工作，原因是 confirmation_target_reached。这是协作式准入判定，不是任务已经暂停。

任一适用周期达到触发条件即生效。边距以百分点计，预警边距不得小于确认边距，触发点最高为 100%；边距不会改变实际目标。若首次有效读数已到或低于目标，应立即询问：“当前已到或低于 80%，现在暂停这项任务吗？”不能再描述尚未发生的越线。目标 100 即使在剩余 100% 时也需立即询问；目标 0 不能保证避免额度耗尽。一次读数可触发多个阶段，宿主应合并问题，避免重复询问。

目标模式不能与 --reserve、--threshold 或 --buffer 混用；这些组合会被拒绝。旧版“预留 10%、缓冲 2 个百分点、在 12% 拒绝新工作”的例子只适用于兼容的预留模式。它不会替代用户选择的目标，包括低于 10% 的目标；目标模式的准入线就是目标值，缓冲为 0。

## 事件、确认与实际任务控制

CLI 事件不证明用户已收到通知、已经授权或任务已经暂停。宿主必须实际提问、单独记录用户答复，并在执行动作前核实具体任务的归属和受支持的控制途径；沉默不算同意。缺少受支持的控制途径时，应说明障碍并请用户手动操作，不能任意终止进程或暂停云端任务。--target 不接受 --allow-interrupt。

默认 JSON 中的 confirmation 阶段和 events 用于宿主判断，pause_authorized 和 task_paused 保持 false。事件最多持久化一次，不保证通知送达；重启或漏读事件后，应结合当前阶段和真实对话记录补上尚未提出的问题，不能把没有新事件视为已获同意。

只有用户对该具体任务明确授权且控制途径已经核实，宿主才可执行获准的动作；必须观察任务实际状态后才能报告暂停成功。旧版受管中断仅限编排器拥有、当前 app-server 可访问的确切 thread/turn，不是绕过确认的捷径，也不保证可恢复暂停。检查点状态为 unconfirmed；RPC 中断确认既不代表任务完成，也不代表检查点保存成功或所有脱离会话的工作进程已退出。

## 停止、重启与读数限制

停止时在另一终端使用相同状态目录：

```sh
python3 scripts/quota_guard.py stop --state-dir STATE --format text --locale zh
```

随后检查原会话，确认进程确实退出；停止请求本身不是退出证明。也可在前台按 Ctrl-C。停止监控不会停止被监控的任务。更改目标或监控配置需要新的明确约定，并先确认原监控退出，再按新配置启动。

达到目标后的准入阻止会跨越额度回升、重置及相同任务和目标的重启而保留；这些变化都不会自动恢复工作。只有用户明确要求新的监控周期，且原监控已停止时，才使用 --new-cycle 清除该周期状态；这本身不是暂停或恢复任务的授权，也不能证明任务已恢复。

轮询、报告延迟、重试和其他客户端的并行消耗可能使读数越过目标，不能保证恰好在目标处停下。分别查看各周期及观测时间；缓存、过期、缺失、模拟或无效的读数不能视作当前余额，也不能证明已达到或解除目标条件。重置时间已过仍需重新读取有效数据。codex 是显式选择的额度类别，不能假定适用于所有模型。

访问失败时使用正常审批和登录流程，勿更改权限、认证配置或 CODEX_HOME 来绕过限制，也勿直接读取凭据文件或会话日志。监控不会购买额度，也不授予额外任务控制权限。
